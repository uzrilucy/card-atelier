01 · GETTING STARTED시작과 작업 흐름

카드 아틀리에는 제작용 원본을 브라우저에 저장하고 완성한 파일을 실리태번으로 옮기는 도구입니다. AI와 대화하는 앱이나 실리태번 서버 관리 도구는 아닙니다. 실리태번에서 수정한 내용은 자동으로 되돌아오지 않습니다.

실행 방법

방식실행 방법과 특징
웹앱정적 호스팅에 파일 구조를 유지해 올리고 index.html 주소로 접속합니다. HTTPS 환경에서 브라우저의 앱 설치·홈 화면 추가 기능을 사용할 수 있습니다.
단일 파일카드아틀리에_단일파일.html을 브라우저로 엽니다. 앱 코드와 매뉴얼이 포함되어 있고, 같은 위치의 fonts/가 있으면 동봉 글꼴도 적용됩니다. 기기의 로컬 HTML 실행·저장소 지원에 따라 동작이 달라질 수 있습니다.
로컬 서버개발용으로 폴더에서 python -m http.server 8099를 실행한 뒤 http://localhost:8099에 접속할 수 있습니다.

첫 카드 만들기

  1. 서재에서 새 카드를 누르고 캐릭터 이름을 입력합니다.
  2. 카드 탭에서 이미지, 설명, 성격, 시나리오, 첫 메시지를 작성합니다.
  3. 필요하면 로어북과 정규식 탭에서 설정을 추가하거나 JSON을 가져옵니다.
  4. 버전 탭에서 버전 번호와 변경 내용을 남깁니다.
  5. 내보내기에서 점검표를 확인하고 카드 PNG를 받습니다.
  6. 제작 원본 보관용으로 프로젝트 백업(.catl)도 받아두고, 카드 PNG를 실리태번에 가져옵니다.
앱 버전과 캐릭터 버전은 별개입니다.

앱 v0.1.1은 도구의 버전입니다. 프로젝트 상단의 버전은 작업 버전이며, 카드 기본 정보의 ‘캐릭터 버전’은 배포 카드 안에 들어가는 값입니다. 버전 저장 시 둘을 함께 바꾸는 옵션이 있습니다.

매뉴얼은 서재의 매뉴얼, 편집 화면 오른쪽 위의 책 아이콘, 또는 설정 → 사용 매뉴얼 열기로 다시 열 수 있습니다. 닫기를 누르면 편집 화면으로 돌아갑니다.

02 · LIBRARY서재와 가져오기

서재는 프로젝트 목록입니다. 카드를 누르면 편집 화면이 열리며, 카드 이름·태그로 검색하고 최근 수정 / 이름순으로 정렬할 수 있습니다.

서재의 ‘가져오기’

이 버튼은 파일을 새 프로젝트로 엽니다. 여러 파일을 함께 선택할 수 있고, 서재에 파일을 끌어다 놓아도 같은 흐름으로 가져옵니다.

파일가져오는 내용
카드 PNG이미지와 PNG 내부의 카드 데이터. V2/V3 데이터가 함께 있으면 V3를 먼저 읽습니다.
카드 JSONV1·V2·V3 카드 데이터. JSON 자체에는 카드 이미지가 없으므로 이미지는 따로 넣습니다.
월드인포 JSON해당 로어북을 가진 새 프로젝트를 만듭니다. 기존 카드에 넣으려면 그 카드를 먼저 열어주세요.
정규식 JSON정규식 한 개 또는 스크립트 배열을 가진 새 프로젝트를 만듭니다.
일반 이미지이미지를 표지로 하는 새 프로젝트. 카드 데이터가 없는 PNG도 해당합니다.
.catl 백업프로젝트와 포함된 이미지·버전 기록을 복원합니다. 같은 프로젝트 ID가 이미 있으면 사본으로 가져옵니다.

카드의 ‘더 보기’ 메뉴

  • 열기: 편집 화면으로 이동합니다.
  • 복제: 현재 카드 내용을 새 프로젝트로 복사합니다. 기존 프로젝트의 버전 기록을 함께 복제하는 기능은 아닙니다.
  • 백업 파일로 저장: 해당 프로젝트를 .catl로 다운로드합니다.
  • 휴지통으로: 서재에서 숨깁니다. 휴지통에서 되살릴 수 있습니다.

휴지통의 완전히 삭제는 프로젝트와 그 버전 기록을 제거합니다. 필요한 원본은 먼저 백업해두세요.

기존 카드에 JSON만 추가하려면?

서재의 가져오기가 아니라 06. JSON을 카드에 넣기 절차를 사용하세요. 프로젝트를 열어둔 상태에서 파일을 놓으면 월드인포·정규식은 현재 카드에 추가됩니다.

03 · CHARACTER CARD카드 편집

필드 묶음의 제목을 누르면 펼치거나 접을 수 있습니다. 긴 텍스트 칸 옆 크게 쓰기 아이콘으로 편집창을 넓힐 수 있고, 입력은 원래 칸에 즉시 반영됩니다. 닫기나 Esc는 취소가 아닙니다.

이미지

  • 이미지 넣기 / 바꾸기: 파일 선택 또는 이미지 영역에 끌어놓기로 설정합니다. 카드 PNG를 이미지 칸에 넣으면 이미지 교체로 처리되므로, 카드 전체를 열 때는 서재의 가져오기를 사용하세요.
  • 2:3 자르기: 이미지 가운데를 기준으로 세로 2:3 비율로 자릅니다. 잘린 부분을 복구할 원본은 별도로 보관하세요.
  • 이미지 빼기: 현재 표지를 제거합니다. 이미지 없이 PNG를 내보내면 이름이 적힌 자동 표지를 만듭니다.
  • PNG는 별도 자르기를 하지 않으면 픽셀을 다시 압축하지 않고 사용합니다. 다른 이미지 형식은 PNG로 변환합니다.

토큰 수 보는 법

각 긴 칸의 토큰·글자 수와 왼쪽 요약 막대는 분량을 가늠하는 보조 지표입니다. 요약에는 설명, 성격, 시나리오, 예시 대화, 캐릭터 노트, 켜진 상시 로어북 내용이 포함됩니다. 실제 모델 토크나이저나 모든 시스템 프롬프트를 계산한 결과는 아닙니다.

04 · WORLD INFO로어북 · 월드인포

이 앱의 로어북은 실리태번의 월드인포를 편집하는 곳입니다. 세계관, 인물, 장소, 사건을 엔트리로 나누고 필요한 때만 프롬프트에 들어가도록 조건을 정합니다.

기본 작성 순서

  1. 엔트리 추가를 누릅니다.
  2. 제목, 발동 방식, 키워드, 내용을 입력합니다.
  3. 삽입 위치와 순서를 정합니다. 깊이 지정 삽입이면 깊이·역할도 설정합니다.
  4. 필요한 경우 세부 조건을 펼쳐 확률·그룹·재귀·시간 효과 등을 지정합니다.
  5. 오른쪽 위 사용을 켜고 목록에서 제목과 토큰 수를 확인합니다.
발동 방식의미
키워드검색 대상에서 키워드가 발견되면 발동 후보가 됩니다. 키워드는 Enter나 쉼표로 추가하며 /정규식/ 형태도 사용할 수 있습니다.
상시키워드 없이 포함되는 설정입니다. 확률·예산·기타 실리태번 조건은 별도로 영향을 줄 수 있습니다.
벡터의미 유사도 검색에 사용합니다. 실제 발동에는 실리태번의 벡터 관련 설정이 필요하며, 앱 안에서 의미 검색을 실행하지는 않습니다.

보조 키워드 논리

주 키워드 조건과 함께 사용할 보조 키워드를 설정합니다. 보조 키워드를 입력하고 원하는 논리를 선택하세요. 가져온 엔트리의 세부 설정에 따라 동작할 수 있으므로 실리태번에서도 확인하세요.

  • AND ANY: 보조 키워드 중 하나 이상이 있어야 합니다.
  • AND ALL: 보조 키워드가 전부 있어야 합니다.
  • NOT ANY: 보조 키워드가 하나도 없어야 합니다.
  • NOT ALL: 보조 키워드 전부가 동시에 있지는 않아야 합니다.

삽입 위치와 로어북 설정

삽입 위치는 캐릭터 정의 앞·뒤, 예시 대화 앞·뒤, 작가 노트 앞·뒤, 깊이 지정, 아웃렛의 8종입니다. 아웃렛은 지정한 {{outlet::이름}} 위치에 내용을 넣을 때 사용합니다. 순서는 목록에서 위아래로 옮기는 것과 별도인 삽입 순서 값입니다.

화면의 로어북 설정을 펼치면 로어북 이름, 스캔 깊이, 토큰 예산, 재귀 스캔을 지정할 수 있습니다. 비워둔 전역 상속 값과 0은 같은 뜻이 아닙니다. 설정의 실제 해석은 실리태번에서 확인하세요.

목록과 인덱스

전체·키워드·상시·꺼짐 필터와 검색을 사용해 엔트리를 찾습니다. ‘더 보기’에서 복제, 위아래 이동, 삭제를 할 수 있습니다. 좁은 화면에서는 엔트리를 누른 뒤 상세 화면이 열리며, 뒤로 버튼으로 목록으로 돌아갑니다.

인덱스 만들기 / 갱신는 켜진 비상시 엔트리 중 키워드가 있는 항목들의 제목과 키워드를 모아 하나의 상시 엔트리로 만듭니다. 인덱스는 본문을 대신 불러오는 기능이 아니며 스스로 토큰을 사용합니다. 엔트리를 변경한 후에는 필요할 때 직접 갱신하세요.

05 · REGEX정규식과 테스트

정규식은 특정 문자열을 찾아 다른 문자열이나 HTML로 바꾸는 규칙입니다. 이 화면의 규칙은 카드에 넣을 수 있는 캐릭터 전용 정규식입니다. 목록 위에서 아래로 순서대로 처리되므로 규칙 간 순서가 중요합니다.

규칙 작성

  1. 정규식 추가를 누르고 이름을 적습니다.
  2. 찾을 정규식을 입력하고 패턴 검사 결과를 확인합니다.
  3. 바꿀 내용에 치환문을 입력합니다. $1, $2는 캡처 그룹, {{match}}는 매칭 전체를 의미합니다.
  4. 사용자 입력, AI 출력, 슬래시 명령, 월드 인포, 추론 중 적용 위치를 선택합니다.
  5. 화면 표시·프롬프트 적용 옵션을 정하고 아래 테스트 입력으로 결과를 확인합니다.
찾을 정규식: /<status>([\s\S]*?)<\/status>/g
바꿀 내용: <div style="padding:12px;border:1px solid #a38bbd">$1</div>
테스트 입력: <status>Day 1 · 맑음</status>

위 예시는 <status> 안의 내용을 테두리가 있는 상자로 바꿉니다. 패턴 끝의 g는 여러 매칭을 모두 치환합니다. HTML을 실제 태그로 작성할 때는 코드 예시의 &lt; 같은 엔티티가 아니라 <, > 문자를 사용합니다.

옵션의미
사용끄면 규칙은 남지만 비활성화됩니다.
잘라낼 문자열캡처 결과에서 제거할 문자열 목록입니다.
화면 표시에만 적용표시 변환에 사용할 규칙입니다. 상태창 HTML처럼 화면만 꾸밀 때 활용합니다.
프롬프트에만 적용AI에 보내는 텍스트 변환용입니다. 표시 옵션과의 조합에 따른 결과는 실리태번에서 확인합니다.
편집할 때도 실행메시지를 편집할 때 규칙을 실행할지 정합니다.
정규식 안 매크로치환 안 함, 원문 그대로, 이스케이프를 선택합니다. 가져온 설정도 보존됩니다.
최소 · 최대 깊이실리태번에서 규칙을 적용할 메시지 깊이 범위를 지정합니다. 비우면 제한하지 않는 값으로 저장됩니다.

테스트 벤치

  • 이것만: 현재 선택한 규칙만 시험합니다. 선택 규칙이 꺼져 있어도 이 모드에서는 시험할 수 있습니다.
  • 켜진 것 전부: 켜져 있고 ‘AI 출력’에 적용되는 규칙을 위에서 아래로 연결해 시험합니다. 다른 적용 위치의 모든 규칙까지 실행하는 모드는 아닙니다.
  • 결과 원문: 치환된 문자열을 그대로 보여줍니다.
  • 미리보기: 치환 결과를 HTML로 표시합니다. 스크립트는 실행하지 않습니다. 외부 이미지·글꼴·스타일 주소는 브라우저가 요청할 수 있습니다.
  • 줄바꿈을 <br>로: 미리보기에서 개행을 화면 줄바꿈으로 표현할지 선택합니다.
  • {{user}} · {{char}}: 미리보기 이름과 현재 카드 이름을 사용합니다. 사용자 이름은 설정에서 바꿉니다.

테스트 문장은 카드 프로젝트 안에만 저장되고 배포 카드에는 들어가지 않습니다. 미리보기는 실리태번의 마크다운, 테마 CSS, 모든 매크로·실행 조건을 재현하지 않는 근사 도구입니다.

한 줄로 압축은 치환문의 줄바꿈과 인접 공백을 한 줄로 정리합니다. <pre> 안의 개행처럼 의미 있는 줄바꿈도 바뀔 수 있으니 먼저 복제하거나 버전을 남긴 뒤 사용하세요. ‘더 보기’에서는 복제, JSON 복사, 위아래 이동, 삭제를 할 수 있습니다.

06 · IMPORT INTO CARD정규식 · 월드인포 JSON을 카드에 넣기

이미 들어 있는 기능입니다.

현재 프로젝트를 열고 각 탭의 ‘가져오기’를 사용하면 됩니다. 이번 업데이트에서는 가져오기 동작을 변경하지 않았습니다.

A. 월드인포 JSON 추가 또는 교체

  1. 서재에서 넣을 대상 카드를 엽니다.
  2. 로어북 → 가져오기를 누르고 월드인포 .json을 선택합니다. 로어북이 내장된 카드 PNG·JSON에서도 엔트리를 가져올 수 있습니다.
  3. 현재 엔트리가 있으면 이어 붙이기 / 통째로 바꾸기 / 취소 중 선택합니다. 비어 있으면 바로 추가합니다.
  4. 이어 붙이기는 기존 항목 뒤에 새 UID로 추가합니다. 이름이 같아도 자동으로 병합·덮어쓰기하지 않습니다.
  5. 통째로 바꾸기는 로어북을 가져온 내용으로 교체합니다. 교체 전에 자동 저장 지점을 남깁니다.
  6. 내보내기 → 로어북을 카드에 넣기를 켜고 새 카드 PNG 또는 카드 JSON을 내보냅니다.

B. 정규식 JSON 추가

  1. 대상 카드를 열고 정규식 → 가져오기를 누릅니다.
  2. 실리태번에서 내보낸 정규식 .json을 선택합니다. 여러 JSON 파일을 동시에 선택할 수 있습니다.
  3. 스크립트 한 개의 JSON 또는 스크립트 객체만 들어 있는 배열을 사용할 수 있습니다. 카드 PNG·JSON을 선택하면 내장된 정규식을 추출합니다.
  4. 가져온 규칙은 현재 목록 뒤에 추가됩니다. 자동 교체·이름 기준 중복 제거는 하지 않습니다. 같은 ID가 있으면 새 ID를 부여해 추가합니다.
  5. 사용 여부, 실행 순서, 적용 위치를 점검하고 테스트합니다.
  6. 내보내기 → 정규식을 카드에 넣기를 켜고 새 카드를 내보냅니다.

C. 파일 끌어다 놓기

프로젝트를 연 상태에서 앱의 일반 영역에 월드인포 JSON 또는 정규식 JSON을 놓으면 현재 카드에 추가됩니다. 월드인포도 교체 질문 없이 이어 붙입니다. 다른 카드 PNG·백업을 놓으면 새 카드로 가져올지 묻습니다. 이미지 영역은 이미지 교체로 별도 처리됩니다.

지원 형식과 주의점

대상이 버전의 파일 인식 기준
월드인포최상위에 entries 객체 또는 배열이 있는 실리태번 월드인포 JSON. 카드에 내장된 character_book은 카드 파일을 통해 가져오는 방법이 확실합니다. 별도로 추출한 character_book JSON의 모든 세부 필드 변환을 보장하지는 않습니다.
정규식findRegex가 있는 스크립트 객체, 또는 모든 요소가 그런 객체인 비어 있지 않은 배열. 최상위를 regex_scripts 같은 별도 객체로 감싼 묶음은 파일 판별 단계에서 인식되지 않을 수 있습니다. 실리태번에서 규칙별 JSON으로 내보내 가져오세요.
ZIP앱 가져오기에서 ZIP을 바로 풀지 않습니다. 정규식 ZIP·전체 백업 ZIP은 먼저 압축을 풀고 내부 JSON·.catl 파일을 선택합니다.
빈 파일 · 다른 형식엔트리나 스크립트가 없거나 지원 구조가 아니면 가져올 내용이 없다는 안내 또는 형식 오류가 나올 수 있습니다. 확장자를 바꾸는 것만으로 호환되지는 않습니다.
가져오기와 카드 내장은 두 단계입니다.

프로젝트에 추가한 뒤에도 내보내기에서 해당 내장 옵션을 꺼두면 배포 카드에는 포함되지 않습니다. 새로 내보낸 파일을 실리태번에 가져와야 변경 사항이 반영됩니다.

이미 배포한 정규식을 갱신할 때는 먼저 버전을 남기고 기존 규칙을 정리한 뒤 새 JSON을 추가하세요. 같은 규칙을 반복해서 가져오면 목록에 중복되어 여러 번 적용될 수 있습니다.

07 · WORK NOTES제작 메모

메모 추가로 제목과 본문을 적고, 고정으로 자주 보는 메모를 위에 배치합니다. 작업 목록, 테스트 결과, 나중에 넣을 설정, 배포글 초안 등에 사용하세요. 고정 메모가 먼저, 그 안에서는 최근 수정한 메모가 먼저 표시됩니다.

메모는 배포 카드 PNG·카드 JSON에는 포함되지 않습니다. 전체 묶음 ZIP에는 ‘제작 메모.md’로, 프로젝트 백업에는 편집 가능한 데이터로 포함됩니다. 버전 저장 시 메모도 함께 기록되므로 저장한 지점으로 되돌리면 메모도 그 상태가 됩니다.

08 · VERSION HISTORY버전과 되돌리기

자동 저장은 현재 상태를 보관하고, 버전 기록은 특정 시점의 사본을 보관합니다. 배포 전이나 큰 수정 전에 수동 버전을 남기면 변경 비교와 복구가 쉽습니다.

수동 버전 남기기

  1. 버전 탭에서 새 버전 번호를 적습니다.
  2. 작은 수정 / 기능 추가 / 대규모 개편 버튼으로 번호를 올릴 수 있습니다. 예를 들어 1.2.3은 각각 1.2.4, 1.3.0, 2.0.0이 됩니다.
  3. 바뀐 내용을 한 줄에 하나씩 적습니다.
  4. 필요하면 카드의 캐릭터 버전도 같이 바꾸기를 켜고 버전 저장을 누릅니다.
기능사용법
지금과 비교저장 지점과 현재 프로젝트를 비교합니다. 카드 텍스트, 로어북·정규식의 추가·삭제·수정 등을 확인합니다.
이전 버전과 비교이전 수동 버전과 해당 수동 버전을 비교합니다.
되돌리기프로젝트의 여러 편집 내용을 선택한 지점으로 복원합니다. 현재 상태는 먼저 자동 저장 지점으로 남깁니다.
이 버전 PNG현재 편집을 되돌리지 않고 과거 수동 버전의 카드 PNG를 다운로드합니다.
업데이트 기록 복사수동 버전의 번호·날짜·변경 메모를 마크다운으로 복사합니다.
자동 저장 지점 보기평소 숨겨진 자동 기록을 펼칩니다. 가져오기 교체·되돌리기 전 기록도 여기서 찾습니다.
기록 삭제그 기록만 삭제합니다. 삭제한 기록은 되살릴 수 없습니다.

수동 버전은 직접 삭제하기 전까지 보관됩니다. 자동 저장 지점은 최근 30개를 유지합니다. 기본 간격은 10분이며 설정에서 바꿀 수 있습니다. 간격은 변경 내용이 저장되는 시점에 확인하므로, 아무것도 하지 않아도 정확히 매 10분마다 새 지점이 만들어지는 타이머는 아닙니다.

비교 화면은 모든 미지원 메타데이터를 검사하는 범용 JSON 비교기가 아닙니다. 배포 전에는 주요 필드와 실제 파일도 확인하세요.

09 · EXPORT내보내기와 실리태번 배포

내보내기 전 확인

점검표는 이름, 첫 메시지·설명 누락, 잘못된 정규식, 적용 위치 누락, 키워드·내용 없는 엔트리, 이미지 상태 등을 알려줍니다. 고치러 가기가 있으면 해당 탭으로 이동합니다. 점검표는 안내이며 모든 경고가 다운로드를 차단하는 것은 아닙니다.

로어북을 카드에 넣기, 정규식을 카드에 넣기를 원하는 대로 선택합니다. 파일 이름은 {name}, {version}, {date}를 사용할 수 있으며 기본은 {name}_v{version}입니다. 날짜 치환은 UTC 기준이라 한국 자정 직후에는 전날 날짜가 나올 수 있습니다.

출력포함 내용과 목적
카드 PNG이미지와 V2 chara·V3 ccv3 데이터를 함께 기록합니다. 실리태번에 가져올 대표 배포 파일입니다. 생성 직후 내부 JSON을 다시 읽어 비교하며, 이 경로의 검증이 실패하면 내보내지 않습니다.
월드인포 JSON로어북을 별도 실리태번 월드인포 파일로 내보냅니다. 카드 내장 옵션과 별개입니다.
정규식 JSON한 개면 JSON, 여러 개면 규칙별 JSON을 ZIP으로 묶습니다. 압축을 풀어 실리태번 정규식 가져오기에 사용합니다.
카드 JSON V2 / V3이미지를 제외한 카드 데이터입니다. V3 전용 필드가 필요한 경우 V3를 선택합니다. 내장 옵션도 반영됩니다.
전체 묶음 ZIP카드 PNG, 존재하는 월드인포·정규식, 수동 버전의 업데이트 기록, 작성한 제작 메모를 묶습니다. 전체 편집 이력을 보존하는 프로젝트 백업과 다릅니다.
프로젝트 백업 .catl프로젝트, 메모, 테스트 샘플, 내보내기 설정, 버전 기록, 연결된 이미지를 보관하는 편집 원본입니다. 다른 기기의 카드 아틀리에 서재에서 가져옵니다.

실리태번에서 확인할 순서

  1. 새로 내보낸 카드 PNG를 실리태번의 캐릭터 가져오기로 엽니다.
  2. 기존 캐릭터를 갱신할 때는 먼저 실리태번 쪽 원본도 보관하고, 사용 중인 버전의 교체·갱신 절차에 맞게 적용합니다.
  3. 내장 월드인포를 가져오는 안내가 나오면 내용을 확인하고, 해당 캐릭터에 올바른 로어북이 연결되어 있는지 확인합니다.
  4. 정규식 확장의 캐릭터 전용(Scoped) 목록, 사용 여부, 적용 위치를 확인합니다. 사용 중인 버전의 승인·활성화 안내가 있으면 확인합니다.
  5. 첫 메시지, 대체 인사말, 로어북 발동, 정규식 출력 결과를 실제 채팅에서 시험합니다.

같은 규칙을 카드 내장과 전역 JSON으로 동시에 설치하면 중복 적용될 수 있습니다. 월드인포도 카드 내장과 별도 파일을 중복 연결하지 않았는지 확인하세요. V2 출력에는 닉네임·그룹 전용 인사말 등 V3 전용 필드가 빠집니다.

10 · SAVE & BACKUP저장 · 백업 · 설정

자동 저장과 상태 표시

입력 뒤 약 0.4초 동안 추가 입력이 없으면 브라우저의 IndexedDB에 저장합니다. 편집 화면 상단에서 저장 대기 → 저장 중 → 저장됨을 확인하세요. 화면을 숨기거나 떠날 때도 저장을 시도하지만, 강제 종료 전에 항상 완료되는 것은 아닙니다. Ctrl+S 또는 ⌘+S로 저장을 요청할 수도 있습니다.

저장 실패가 보이면 저장 공간·브라우저 권한을 확인하고 현재 내용의 파일 백업을 받으세요. ‘저장됨’은 이 기기의 현재 브라우저에 저장됐다는 뜻이며, 클라우드 동기화나 다운로드를 뜻하지 않습니다.

다른 창에서 수정했다는 안내

다른 창의 저장이 감지되면 이 창의 자동 저장을 멈춰 덮어쓰기를 줄입니다. 이 창에만 남은 내용이 있으면 먼저 복사해두고 최신 내용 불러오기를 누르세요. 충돌 감지는 완전한 동시 편집 기능이 아니므로 같은 카드는 한 창에서 작업하는 것이 좋습니다.

설정 항목

  • 화면 테마: 시스템 / 어둡게 / 밝게 중 선택합니다.
  • {{user}} 미리보기 이름: 정규식 테스트에서 사용할 이름입니다.
  • 자동 저장 지점 간격: 5분 / 10분 / 20분 / 30분입니다. 현재 내용의 0.4초 자동 저장 간격을 바꾸는 설정은 아닙니다.
  • 저장 공간 고정 요청: 브라우저에 지속 저장을 요청합니다. 승인 여부는 브라우저가 결정하며 직접 데이터 삭제까지 막아주는 기능은 아닙니다.
  • 모든 카드 백업 받기: 휴지통을 제외한 프로젝트들을 각각 .catl로 만들어 ZIP으로 받습니다.
  • 사용 매뉴얼 열기: 지금 보고 있는 문서를 엽니다.

기기·주소를 바꿀 때

  1. 기존 환경의 내보내기 → 프로젝트 백업 → 백업 받기로 .catl 파일을 받습니다.
  2. 다른 기기에 파일을 전달합니다.
  3. 새 환경의 서재에서 가져오기로 .catl 파일을 엽니다.
  4. 프로젝트·이미지·버전 기록을 확인한 뒤 작업을 이어갑니다.
브라우저 데이터 삭제 전에 백업하세요.

다른 기기, 다른 브라우저, 다른 호스팅 주소, 단일 파일 실행은 저장소가 다를 수 있습니다. 시크릿 창, 사이트 데이터 삭제, 브라우저 재설치로 작업이 사라질 수 있으므로 중요한 원본은 .catl 파일로 별도 보관하세요.

웹앱은 서비스 워커로 앱 파일을 캐시합니다. 최초 접속과 캐시가 준비된 뒤에는 오프라인 실행이 가능하며, 사용하지 않은 글꼴 조각이나 외부 주소로 연결한 자료는 오프라인에서 없을 수 있습니다. 업데이트 안내가 뜨면 저장을 확인하고 같은 앱의 창을 모두 닫은 뒤 다시 여세요.

11 · WORKFLOWS상황별 작업 예시

이미 배포한 봇을 갱신하고 싶어요

  1. 제작 원본이 있으면 해당 프로젝트를 엽니다. 실리태번에서만 수정한 최신 내용이 있으면 먼저 최신 카드 PNG를 내보내 서재의 새 프로젝트로 가져옵니다.
  2. 수정 전 상태를 버전으로 저장하고 필요하면 .catl도 받습니다.
  3. 카드 텍스트·인사말·로어북·정규식을 수정합니다. 월드인포는 교체 또는 추가를 선택할 수 있고, 정규식은 추가되므로 기존 규칙을 직접 정리합니다.
  4. 테스트와 버전 비교 후 새 버전 번호·변경 내용을 저장합니다.
  5. 카드 탭의 제작자 노트에 업데이트 기록 넣기를 누릅니다. 이 변경까지 과거 버전에 남기려면 이후 버전도 저장하세요.
  6. 내장 옵션을 확인하고 새 카드 PNG와 .catl 백업을 받습니다.

세계관은 따로, 카드만 가볍게 배포하고 싶어요

내보내기에서 로어북을 카드에 넣기를 끄고 카드 PNG와 월드인포 JSON을 각각 받습니다. 사용자는 실리태번에서 월드인포를 별도로 가져오고 해당 캐릭터에 연결해야 합니다. 정규식도 같은 방식으로 내장 여부를 따로 정할 수 있습니다.

실수로 로어북 전체를 바꿨어요

버전 → 자동 저장 지점 보기에서 ‘로어북 바꾸기 전 백업’을 찾고 비교한 뒤 되돌립니다. 되돌리기는 로어북만이 아니라 그 시점의 프로젝트 전체에 적용되므로 이후에 작성한 다른 내용은 먼저 복사·백업해두세요.

태블릿과 PC에서 번갈아 작업하고 싶어요

.catl을 작업 이동용 원본으로 사용합니다. 가장 최근에 작업한 쪽에서 백업을 받아 다른 쪽으로 가져오세요. 같은 프로젝트가 이미 있으면 사본이 생기므로 이름과 버전을 확인하고, 필요 없는 오래된 사본은 백업 후 정리합니다. 두 기기의 내용을 자동 병합하는 기능은 없습니다.

12 · TROUBLESHOOTING문제 해결과 알려진 한계

가져왔는데 기존 카드에 안 들어가고 새 카드가 생겨요.

서재의 가져오기는 새 프로젝트를 만듭니다. 대상 카드를 먼저 열고 로어북·정규식 탭의 가져오기를 사용하세요.

월드인포·정규식을 넣었는데 실리태번에서 안 보여요.

내보내기의 카드 내장 옵션을 확인하고 새 파일을 다시 받으세요. 실리태번에는 새로 만든 파일을 가져와야 합니다. 실리태번 쪽 로어북 연결, 캐릭터 전용 정규식 사용 여부와 승인 안내도 확인합니다.

JSON인데 형식 오류가 나거나 가져올 항목이 없대요.

JSON 문법과 실제 데이터 구조를 확인하세요. 앱이 읽는 정규식은 단일 스크립트 또는 스크립트 배열입니다. 임의의 래퍼 객체, 다른 플랫폼 전용 형식, 빈 파일, 압축된 ZIP은 그대로 가져오지 못할 수 있습니다. 지원 형식 표를 참고하세요. 한글 JSON은 UTF-8로 저장하는 것이 좋습니다.

정규식이 두 번 적용되거나 출력이 꼬여요.

규칙을 반복해서 가져왔는지, 목록 순서가 바뀌었는지 확인합니다. 실리태번의 전역 정규식과 카드 전용 정규식에 같은 규칙이 동시에 있는지도 점검하세요.

로어북이 발동하지 않아요.

사용 여부, 키워드, 보조 키워드 논리, 검색 깊이, 확률, 예산, 그룹·재귀 조건을 확인합니다. 벡터 방식은 실리태번의 관련 설정이 필요합니다. 이 앱은 로어북 실제 발동을 시뮬레이션하지 않습니다.

테스트 미리보기와 실리태번 화면이 달라요.

앱은 HTML·일부 매크로 치환의 근사 미리보기입니다. 실리태번 마크다운, 테마 CSS, 모든 매크로·깊이 제한·실행 옵션을 재현하지 않습니다. 결과 원문도 확인하고 실리태번에서 최종 시험하세요.

매뉴얼을 열었는데 빈 화면이에요.

일반 웹앱에서는 index.html과 같은 위치에 manual.html을 업로드해야 합니다. 최신 js/ui/manual.js와 앱 파일도 함께 갱신하세요. 단일 파일판은 매뉴얼이 안에 포함되어 있어 최신 단일 HTML 자체를 다시 열면 됩니다.

업데이트했는데 예전 화면이 계속 보여요.

같은 앱의 모든 창을 닫았다가 다시 엽니다. 정적 호스팅 파일이 제대로 갱신됐는지 확인하세요. ‘사이트 데이터 전체 삭제’는 프로젝트까지 지울 수 있으니 먼저 .catl 백업을 받으세요.

백업 ZIP을 가져오지 못해요.

ZIP은 먼저 압축을 풉니다. 프로젝트 복원은 안의 .catl, 정규식 추가는 안의 .json을 가져옵니다. 전체 묶음 ZIP은 프로젝트 이력을 모두 포함하는 백업이 아닙니다.

다른 브라우저에서 카드가 사라졌어요.

각 브라우저·주소는 저장소가 다를 수 있습니다. 원래 환경으로 돌아가 .catl을 받은 뒤 새 환경에 가져오세요. 이미 사이트 데이터가 지워졌고 별도 백업이 없다면 복구를 보장할 수 없습니다.

배포 카드만 있으면 제작 메모와 버전도 복구되나요?

아니요. 카드 PNG·카드 JSON은 배포용 데이터입니다. 메모·테스트 입력·버전 기록까지 옮기려면 .catl 프로젝트 백업을 사용하세요. 과거 버전 복구도 백업에 해당 기록이 포함되어 있어야 가능합니다.
